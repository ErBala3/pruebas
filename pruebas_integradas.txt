1. Introducción
El presente documento recoge la planificación, descripción, ejecución y resultados de las pruebas integradas realizadas sobre la aplicación web Fichaje mediante QR. A diferencia de las pruebas unitarias, orientadas a comprobar funciones o componentes aislados, las pruebas integradas se centran en verificar el comportamiento conjunto de varios módulos trabajando de forma coordinada dentro de flujos completos de uso.

En este proyecto, el sistema integra autenticación de usuarios, gestión de empleados, generación y descarga de códigos QR, registro de fichajes, cálculo de resumen de horas, control de accesos por rol, gestión de usuarios asociados a empleados, almacenamiento de datos complementarios del fichaje y mantenimiento de la persistencia en base de datos.

Este documento se ha ampliado y completado tomando como referencia la implementación real del proyecto contenida en el repositorio `ErBala3/pruebas`, especialmente la aplicación Flask ubicada en `fichaje_qr/app.py`, la suite automatizada `fichaje_qr/tests/test_fichaje.py` y la documentación complementaria de pruebas unitarias reflejada en `pruebas_unitarias.txt`.

2. Objetivo
Los objetivos de estas pruebas integradas son los siguientes:
- comprobar la correcta interacción entre módulos o funcionalidades relacionadas;
- verificar que el intercambio de datos entre componentes se realiza correctamente;
- validar flujos completos de uso dentro de la aplicación;
- detectar errores que no aparecen en pruebas unitarias aisladas;
- asegurar la coherencia entre respuestas API, sesión y persistencia en base de datos;
- documentar formalmente los resultados obtenidos y las incidencias detectadas.

3. Alcance
Este documento incluye las pruebas integradas realizadas sobre los flujos funcionales principales de la aplicación web, combinando módulos como:

4. Descripción general del proyecto
La aplicación Fichaje mediante QR ha sido desarrollada con la finalidad de realizar fichajes de entrada y salida en una empresa mediante un código QR único asociado a cada empleado. El sistema permite que un administrador gestione empleados y usuarios, descargue códigos QR, consulte fichajes e interprete resúmenes anuales de horas. Además, la aplicación permite registrar fichajes con cierta información contextual adicional, como coordenadas geográficas o nombre de tienda.

La versión principal del proyecto está implementada con Python y Flask, utilizando SQLite como base de datos. El repositorio también contiene versiones y componentes alternativos en Node.js, pero el alcance de este documento se centra en la implementación principal localizada en `fichaje_qr/`, ya que es la que define el flujo funcional probado mediante los casos integrados descritos en este archivo.

6. Criterios de aceptación
Una prueba integrada se considerará superada cuando todos los módulos implicados en el escenario funcionen de forma coordinada y el flujo completo produzca el resultado esperado.

Se considerará no superada cuando:
- falle la comunicación entre módulos;
- los datos no se transfieran correctamente;
- la base de datos no refleje el resultado esperado;
- se produzca un error no controlado durante la ejecución del escenario;
- la respuesta del sistema no coincida con la lógica funcional definida en el proyecto;
- se detecte incoherencia entre la API, la sesión o la persistencia.

- la persona responsable;
- las precondiciones;
- los datos de entrada;
- los pasos de ejecución;
- la salida esperada;
- la salida obtenida;

- las observaciones o incidencias detectadas.
